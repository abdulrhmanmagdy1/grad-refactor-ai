## E2 — Accept the long-parameter-list parameter-object refactor

**Problem:** the adapter's trained completion for `long-parameter-list-test-01..04` introduces a
`@dataclass` request object and changes the function signature. `candidate_selection.score_candidate`
adds `-10_000` for the signature change, `ReviewAgent._signature_violations` rejects before tests,
and `load_dataset_cases` passes `test_code=None`, so the authored smoke test never runs. Result:
4 false negatives; D is 28/28 on the other 7 types.

- **2a — selection flag.** `src/core/candidate_selection.py`: add
  `allow_signature_changes: bool = False` to `score_candidate` and `select_best_candidate`. When
  true, do not add `_INVALID_SCORE` and do not withhold the signature component for the target
  function; still record `signature_violations` in the evidence. Keep syntax, symbol preservation,
  finding resolution, complexity/MI and new-rule penalties unchanged.
- **2b — review flag.** `src/agents/review_agent.py`: add
  `allow_signature_changes: bool = False` to `review`. When true, skip the early signature rejection
  but still run the authored smoke test and the symbol-preservation check. Keep the guard for every
  other refactoring type.
- **2c — thread the flag.** `src/models/local_provider.py` `_generate_hf` (line 261) reads
  `options["allow_signature_changes"]` and forwards it to `select_best_candidate`. The harness passes
  `{"allow_signature_changes": True}` for `case.refactoring_type == "long-parameter-list"` in all
  four groups (A, B, C, D), including the D retry at line 408 and the `RefactoringAgent.refactor`
  calls. Pass the same flag to every `ReviewAgent.review` call. Do **not** infer the exception from
  model output.
- **2d — supply the trusted smoke test.** Do **not** edit `data/curated.jsonl`: it would change the
  dataset SHA `e5b782...` and break the training manifest's `c6c810...` dataset record. Add a
  separate `data/long_parameter_smoke_tests.json` keyed by record id, generated by a small exporter
  that reuses the builders in `scripts/generate_curated_dataset.py` and asserts the regenerated
  prompt equals the dataset prompt before writing. In `load_dataset_cases`, load the smoke test as
  `test_code` for the four `long-parameter-list` **findings** cases; the two clean-control
  long-param records keep `test_code=None` (identity pairs). Fail closed if a findings case has no
  smoke test.
- **2e — targeted rerun (optional).** Add `--case-ids` to the harness CLI so the six long-param
  test cases (4 findings + 2 clean controls) can be rerun without a full 48-case run.
- **Acceptance:**
  - Negative test: an arbitrary signature change on a non-long-param case is still rejected.
  - Negative test: a long-param candidate that drops a parameter without the request object fails
    the smoke test.
  - Positive test: the four authored completions pass the smoke test and are accepted when the flag
    is true.
  - Rerun the six long-param cases; only after 4/4 findings + 2/2 clean, rerun full D (48) before
    any 48/48 claim.
- **Risk:** never disable signature checks globally; that weakens the review guard and can inflate
  other refactoring types.
