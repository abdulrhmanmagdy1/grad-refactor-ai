# سيناريو العرض التوضيحي (8 دقائق)

كل خطوة لها نتيجة متوقعة يمكن التحقق منها على الشاشة؛ إن اختلفت النتيجة توقف واذكر السبب بدل
المتابعة. لا تُعرض أرقام من شرائح محفوظة إن كانت الخدمة تعرض غيرها.

## قبل العرض (10 دقائق قبل الموعد)

```bash
python scripts/doctor.py            # العتاد والأدوات والحزمة وقاعدة البيانات
python scripts/tasks.py all         # كل البوابات خضراء
python scripts/smoke_ui.py          # 8 فحوص دخان
uv run uvicorn refactor_ai.api:app --host 127.0.0.1
```

افتح `http://127.0.0.1:8000` وتحقق من:

- شارة المزودات: `mock` و`smart_ast` متاحان (و`ollama` إن كان الخادم يعمل).
- درج History يفتح ويعرض بطاقة المجاميع.
- تبديل الثيم داكن/فاتح يعمل.

**خطة بديلة**: إن تعذّر تشغيل Ollama يُعرض `mock` فقط وتُذكر الحدود بشفافية؛ لا يُدّعى أن
الموديل المحلي شارك.

## الدقيقة 0–1: المشكلة والواجهة

- اعرض المحرر وقائمة Examples وقل: «التحليل AST فقط، والـAPI لا ينفّذ كودًا مُرسلًا».
- افتح تبويب الشبكة في أدوات المتصفح مرة واحدة لتظهر ترويسات الأمان (`Content-Security-Policy`).

## الدقيقة 1–3: التحليل

1. اختر مثال **Deep nesting**.
2. اضغط **Analyze**.
3. النتيجة المتوقعة: `syntax_valid` أخضر، finding واحد `deep-nesting` مع السطر والسبب، ومقاييس
   بنيوية، ورسم AST في تبويب Graph.
4. لاحظ شريط المصدر: يعرض القاعدة الأكثر تكرارًا ويقترحها كنوع إعادة هيكلة.

## الدقيقة 3–5: التشغيل والمراجعة

1. اضغط **Run refactoring** (أو Ctrl+Enter).
2. النتيجة المتوقعة: مراحل التشغيل تمر أمامك، ثم حكم **approved** وDiff فعلي (شروط مدمجة) وشريط
   الميزانيات يظهر الحدود المستخدمة.
3. افتح تبويب Verification: ثلاث طبقات منفصلة، والاختبارات الذهبية المولدة.
4. اربط التشغيل بـ`X-Request-ID`: افتح أدوات المتصفح → Network → الاستجابة، وطابقه مع سطر السجل
   في الطرفية (JSON فيه `request_id` و`duration_ms`).

## الدقيقة 5–6: التاريخ والمجاميع

1. افتح **History**: بطاقة المجاميع (عدد التشغيلات، نسبة الاعتماد، متوسط المدة) وأعمدة آخر
   التشغيلات.
2. اختر تشغيلين واضغط **Compare**: جدول مقارنة من السجل المخزَّن.
3. صدّر CSV ثم JSON وأظهر أن الأعمدة نفسها بلا اشتقاق.
4. انسخ رابط التشغيل (أيقونة الرابط) وافتحه في تبويب جديد: نفس التشغيل ونفس التبويب.

## الدقيقة 6–7: الصدق في النتائج

- افتح `experiments/dataset_test_summary.json`: مجموعتا A/B بأرقام مقيسة، ومجموعتا C/D بحالة
  `provider_unavailable` وقيم `null`.
- اذكر صراحة: المراجعة البشرية العمياء لم تُملأ بعد، ولا Adapter مدرَّبًا، وأن
  `aggregate_blind_review.py` يرفض التجميع قبل التقييمات.

## الدقيقة 7–8: الخاتمة والأسئلة

- اعرض ناتج `python scripts/smoke_ui.py` (8 فحوص) و`RELEASE_MANIFEST.json` (بصمات).
- الخلاصة: منتج محلي كامل بحدود معلنة، لا خدمات مدفوعة، لا تنفيذ كود مُرسل خارج Runner معزول.
- للأسئلة الصعبة: أعد إلى `docs/requirements/traceability.md` (كل متطلب ودليله) و
  `docs/architecture/decisions.md` (كل قرار وبدائله).
