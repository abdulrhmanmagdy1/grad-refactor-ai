## What has to happen before a release claim

In dependency order, with the owning workstream:

1. Commit the full training record, adapter checksum and reload check, and update the model card (models).
2. Align or explicitly report the generation limits, run the validation baseline for all four arms, record the adapter selection, set targets and write the protocol freeze record (data and evaluation, with models).
3. Run the test split once under the frozen protocol and produce the tables and figures from the records (data and evaluation).
4. Run the service once with the local model and the selected configuration and keep the run records; choose stable demonstration cases from what actually happens (backend, frontend).
5. Reproduce from a clean clone with `uv sync --frozen` and `npm ci`, and record whether it was the same laptop (backend).
6. Refresh the acceptance matrix, this page, `execution-state.json` and the testing page; write the handover file (workflow and verification, coordinator).
7. Write the report and slides from the records, rehearse the demonstration and record the backup (frontend and delivery, all owners).
8. Hold and record the supervisor reviews; record the team inspections above (all members).
