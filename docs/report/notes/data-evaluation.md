## Data

Real code rarely has this pattern in a form the task accepts: 4 of 974 MBPP functions, 1 of 164 HumanEval functions and 4 of 2,630 TheAlgorithms/Python functions qualify. The dataset therefore consists of 81 team-authored template families (795 records) plus the 4 qualifying MBPP/HumanEval functions that also yield trustworthy tests (one MBPP function has an unreachable `return` and was dropped). Targets come from the shared deterministic transformation; explanations are generated from the same planning rules and name the conditions that became guard clauses.

Reference tests are produced only by executing trusted code in a curation-only executor (separate process, fixed hash seed, step budget, temporary directory). Each record has 3 to 10 tests (5,168 in total) that execute every return and raise statement and every reachable branch outcome, and detect 95.1% of 10,807 single-point mutants (all mutants that any candidate input detects). The reference transformation reproduced the original's outcome on every usable candidate input of every record (differential test). A test re-executes all committed tests against original and target.

Splits are by source group: 57 training families, 12 validation families and 12 test families drawn one per category, plus the 4 real functions in the test split. Near-duplicates use the Allamanis (2019) identifier/literal Jaccard rule (0.8 set, 0.7 multiset) without the small-function exemption; none were found across splits (highest 0.32), against the 124 code items of the models workstream's pilot fixtures (highest 0.42) or against the demonstration cases (highest 0.24). A family with the same purpose as a pilot function (`flag-parse`, similarity 0.61) was kept in training as a precaution. The test split was frozen on 2026-10-20. After the coordinator adopted prompt format refactor-v2 on validation-only evidence, the records were re-rendered the same day with unchanged cases: the case-content hash `3a1e6b95ce74dbd1acdd76207eefcead31eeb255cc3b24a1e6d3955f90e75d12` is unchanged, the rendered test hash moved from `b765dbb8…` (refactor-v1) to `27b6d0ec…` (refactor-v2), and the freeze record keeps both freezes ([regeneration record](../../../experiments/data/2026-10-20-refactor-v2-regeneration.json)).

## Evaluation harness

`scripts/evaluate.py` runs arms A to D through the workflow coordinator, meters every provider call itself, rechecks syntax and rubric of each proposal without executing it, records failures, timeouts and harness exceptions as attempts, warms up the runner and model before timing, rotates the arm order per case and never overwrites an existing record file. It refuses the test split without `--i-confirm-frozen-test`, `--protocol-version eval-v1`, a frozen protocol record, the local model, and matching rendered and case-content test-split hashes. `scripts/report_evaluation.py` produces markdown and CSV tables with explicit denominators, paired exact McNemar tests with Holm adjustment, and dependency-free SVG figures, identically on every run from the same records.

## Validation baseline and freeze (2026-10-21)

The four arms ran once on the 84 validation cases with the harness on Kaggle (kernel `grad-refactor-ai-eval-600603dc`; base model at revision `ea3f2471`, adapter `full-2026-10-21` with SHA-256 `dff9ae02…`, Tesla T4, float32). Overall acceptance (proposal_ready over 84): A 6, B 3, C 69, D 46. C beats A (65 against 2 discordant cases, Holm p = 1.2e-16) and D beats B (44 against 1, Holm p = 7.8e-12), but D falls behind C (2 against 25, Holm p = 1.1e-5): D's 23 uncertain cases all pass syntax, rubric and reference tests and fail only because the review output could not be parsed, in 21 of them because the review reached its 384-token limit while repeating one reason. Every review output that reached the limit (87 of 260 in B and D) had started with an accept verdict. B vs A shows no detectable difference (2 against 5, p = 0.45).

The run used a bundle built from ee87a11 with uncommitted changes, before the harness fixes of e4d6f31 and the workflow fixes of f187b63. `experiments/evaluation/validation-2026-10-21/check_code_changes.py` answers whether those fixes change the numbers without loading a model: the current report code reproduces every Kaggle table from the records; the e4d6f31 defects did not occur in this run (no failed run in B, C or D, A's one failure already scored as not run, no runner error with zero tests, no stopped worker); and replaying every deterministic decision with both code versions changes no outcome of A, C or D but leaves three B outcomes undetermined, because the corrected rubric no longer counts a trailing `elif` as a guard clause (two of B's three accepted cases would now get a correction). The targets therefore use B's least favourable attainable counts.

The protocol freeze record fixes the per-arm settings of the validation run (the harness's 768/384 new-token and 2048-input budgets, deliberately not the service's interactive defaults), the model and adapter identity, the Kaggle hardware, the measures and paired tests, the dataset and test-split hashes, the numerical targets (95 % Clopper-Pearson limits of the validation proportions, expected directions only where the validation difference is significant in every attainable outcome) and the SHA-256 of 29 files of workflow, scoring and generation code. It also discloses that the correction prompt of B and D shows failing reference tests, which is oracle feedback. The harness now refuses a test run unless the record matches the run exactly, and `tests/test_evaluation_freeze.py` fails if a frozen file changes without a re-freeze.

## Limitations

The template families share one generator design; held-out families test transfer to unseen domains with similar skeletons (structural similarity to the nearest training record has a median of about 0.36). Real code is a four-case probe and may overlap the base model's pretraining data. Reference tests compare exception types, not messages, and cover only the tested inputs. Comments are not preserved in targets. The team-authored data has no redistribution license yet. The validation baseline comes from one run of 84 cases from 12 families; its frozen targets are thresholds, not hypothesis tests, and the test results are still open. Arms B and D see failing reference tests in their correction prompt, so their acceptance after a correction is optimistic for real use.
