## What the review supports

- **Task choice.** R2 to R5 study broad or large-scale refactoring with large models. A single, catalogued refactoring (R1) with a deterministic reference transformation and executable checks is a defensible, narrower setting for a 0.5B local model.
- **Verification separate from the model.** R3 reports behavior-changing and syntactically invalid LLM refactorings, and R14 shows that weak tests overestimate correctness. We keep syntax, rubric, trusted reference tests and model review as separate results and never treat passing tests as proof of equivalence.
- **Comparison design.** R6 and R7 report gains from role decomposition with large models, while R8 shows that repair gains can disappear once cost is counted. Arms A to D therefore separate fine-tuning (A versus C, B versus D) from coordination (A versus B, C versus D), and every arm reports calls, tokens and latency with the same denominators.
- **Adaptation.** R9 and R10 support LoRA-style PEFT under a small GPU budget; R11 documents the base model family.
- **Data hygiene.** R15 motivates source-group splits and near-duplicate checks; R11 motivates reporting the four MBPP/HumanEval cases separately because of possible pretraining overlap.

No claim of novelty or superiority is made here. Whether coordination or fine-tuning helps a 0.5B model on this task is the open question the evaluation measures; a negative result is a valid outcome.
