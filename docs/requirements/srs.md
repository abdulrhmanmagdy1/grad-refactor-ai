## متطلبات الجودة

- NFR01: لا تُنفذ المدخلات أو المخرجات في عملية API. مرحلة التأسيس تستخدم AST فقط.
- NFR02: تنفيذ الاختبارات لاحقًا لا يبدأ إلا داخل Runner معزول مع حدود CPU/RAM/وقت وشبكة وملفات وصلاحيات، وبمدخلات موثوقة في MVP.
- NFR03: التشغيل الأساسي لا يتطلب API مدفوعًا أو أسرارًا داخل المستودع.
- NFR04: Python 3.11 وملف قفل للبيئة الأساسية، وتعليمات منفصلة لتبعيات GPU.
- NFR05: سجل التجارب يتضمن نسخ الكود والبيانات والموديل والإعدادات والبذور والعتاد.
- NFR06: نجاح الاختبارات لا يُعرض كبرهان كامل على التكافؤ السلوكي.
- NFR07: حدود زمن الاستجابة واستهلاك الذاكرة النهائية تُعتمد بعد القياس على جهاز العرض في الأسبوع الأول.

## حالات الاستخدام

UC01: يدخل المستخدم مثالًا صالحًا، يطلب التحليل، يراجع اقتراحًا ثم يحمّل التعديل.

UC02: يدخل كودًا غير صالح، فيحصل على رسالة خطأ دون تنفيذ أي سطر.

UC03: يفشل الموديل أو التحقق، فيرى السبب ولا يحصل على علامة نجاح مضللة.

UC04: يشغّل الباحث تجربة مقارنة ويستخرج سجلًا لكل حالة مع ملخص إجمالي.

## تتبع المتطلبات

تذكر كل Issue المعرفات المرتبطة بها. تتضمن PRs شروط القبول وأدلة التحقق. حزمة التسليم تتضمن جدولًا بالمتطلبات المنفذة والمستبعدة وروابط الاختبارات. لا تعتبر المتطلبات موافقة أكاديمية حتى تسجيل مراجعة الدكتورة.
